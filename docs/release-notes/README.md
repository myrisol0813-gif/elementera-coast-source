# 开源 APK 更新日志

每次正式发行前，在本目录添加与 Android versionName 完全一致的 Markdown，例如 `0.2.50-source.md`。首行使用 `# 0.2.50-source`，正文至少一条真实变更，不使用待填占位文本；最多 4000 字节。建议按新增、优化、修复、限制与更新方式组织。

只写本次签名安装包实际包含的变化。将尚未启用的功能明确注明，不复制私用数据、账号、私密关系、服务器凭据或后台施工日志。不要将草稿分支测试当作手机实测。已有正式发行的版本保持原 APK、签名、标签与版本号；后续新增修改必须递增 versionCode 与 versionName。

稳定签名发布流程先验证对应日志，再构建、校验签名并使用 `gh release create --notes-file` 发布正文。应用「版本与更新」从现有 GitHub 元数据获取同一正文；新版提示只负责提醒，不自动安装。若缺日志，新的发行应停止，不回落到旧版固定通用说明。
