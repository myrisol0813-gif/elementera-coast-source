# COAST-DEV-HANDS-OWNER-INTENT-CLARIFICATION

## 核心口径

海岸开发手的主体验是模型施工，不是后台控制台按钮集合。

主流程：

```text
屋主用自然语言描述目标
↓
模型自主判断需要读取的仓库 / 文件 / commit / PR / CI / Notion 材料
↓
模型调用真实开发工具
↓
工具结果回灌给模型
↓
模型继续分析、提出代码变更、PR、CI 检查或 Notion 回执
↓
屋主只负责普通写确认、危险动作强确认与最终验收
```

屋主是前端屋主、产品方向、审美与验收人，不是 GitHub 参数操作员。

按钮模式可以保留，但只用于自检、单步辅助与备用入口。复杂开发不得要求屋主手动判断文件、拼 GitHub API 参数、管理 branch / PR 细节或复制代码来回搬运。

## 权限边界

- 读取：模型可直接调用已经开启且位于 allowlist / Notion root 范围内的读工具。
- 普通写入：只生成 pending action，必须收到精确 `确认写入：<动作>` 后才能执行。
- 危险动作：只生成 pending action，必须收到精确 `确认执行危险动作：<动作名称>` 后才能执行。
- 普通“可以”“去吧”“嗯嗯”不能替代确认文本。
- 未确认前，模型与 UI 都不得声称动作已经执行。
- 关闭的工具包不得暴露给模型。
- 普通聊天关闭模型施工模式时，不暴露 GitHub / Notion / CI 开发工具。

危险动作包括但不限于直接推 main、删除文件、批量重写、修改 workflow、重跑 workflow、merge PR、删除 Notion 页面与大段覆盖内容。

## 完成标准

当模型施工模式开启后，屋主说：

> Model Partner，帮我看看仓库。

模型应该能真实读取允许的仓库并继续分析，而不是要求屋主打开参数面板。

写动作示例：

> Model Partner，帮我新建一个测试 issue。

模型应提出 pending action；前端显示确认卡；确认前不执行，精确确认后才执行，并把真实结果重新递回模型继续施工。

## 辅助按钮定位

按钮适合 GitHub / Notion 自检、查看 workflow run、刷新 APK artifact、屋主设置更新、查看脱敏施工日志等单步操作。

按钮不是“开发手完成”的验收标准。模型能基于自然语言自行调用真实工具并继续施工，才算开发手真正接到模型身上。
